# history/ 사용법

이 디렉토리는 SECANT 프로젝트의 **작업 기록(개발 일지)** 을 날짜별로 모아 두는 곳입니다.
보고서의 "실험 과정", 데모 영상의 "개발 흐름", 팀 기여도 명세를 쓸 때 근거 자료로 사용합니다.

## 언제 쓰나?

- **push 할 때마다** 그날의 파일에 변경사항을 추가합니다.
- 같은 날 여러 번 push 하면 **같은 파일에 항목을 이어서** 추가합니다 (새 파일 X).

## 파일 이름 규칙

```
history/YYYY-MM-DD_요일.md
```

- 예: `2026-11-23_Mon.md`, `2026-11-24_Tue.md`
- 요일은 영어 3글자 약어: `Mon` `Tue` `Wed` `Thu` `Fri` `Sat` `Sun`
- 날짜를 앞에 두기 때문에 파일 목록이 자동으로 시간순 정렬됩니다.

## 파일 내용 템플릿

```markdown
# YYYY-MM-DD (요일)

## [HH:MM] 한 줄 요약
- **작업자**: 이름
- **변경 내용**:
  - 무엇을 추가/수정/삭제했는지
- **이유**: 왜 이렇게 바꿨는지
- **결과**: (실험이면) 수치나 관찰, (코드면) 동작 확인 여부
- **다음 할 일**: 이어서 할 작업
```

## 작성 원칙

1. **무엇보다 "왜"를 적는다.** 무엇을 바꿨는지는 코드에 남지만, 왜 바꿨는지는 여기에만 남습니다.
2. **실험 결과는 숫자로 적는다.** 예: "LSTM val RMSE 0.052 → 0.047 (W=24 → 48)".
3. **실패도 적는다.** 안 된 시도와 그 원인은 보고서의 Discussion/Limitations 재료가 됩니다.
4. **짧게.** 한 항목당 5~10줄이면 충분합니다.
